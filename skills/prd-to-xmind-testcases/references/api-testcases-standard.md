# 接口测试用例规范

用户明确要求「按接口测试」「生成接口测试用例」，或 PRD 提供了接口定义（路径、方法、参数、错误码）时加载。与通用设计规范叠加使用，不替代。

## 一、必覆盖维度

### 1.1 请求与参数

- **正常请求**：必填齐全、类型格式正确、取值在约定范围内，校验响应体关键字段。
- **参数校验**：每个必填参数 1 条缺失用例；每个有格式约束的参数（数字、枚举、日期、手机号、邮箱、金额）1 条格式非法用例；有范围/长度的用边界值。
- **可选参数**：覆盖「不传」「传空」「传有效值」三种，说明对结果的影响。

### 1.2 响应与错误码

- **成功响应**：HTTP 状态码、业务码、响应体结构、关键字段含义与文档一致。
- **错误码**：文档定义的每个错误码至少 1 条用例，写清触发条件 + 预期返回（状态码 + 错误码 + 错误信息）。
- **未定义错误**：明显非法请求不应返回 200。

### 1.3 鉴权与权限

- 未带 token / 签名 / session；
- 鉴权失效或过期；
- 鉴权格式错误（前缀缺失、算法不符）；
- 越权访问：A 访问 B 的资源，预期为无权限或空数据，且不泄露他人字段。

### 1.4 幂等与并发

- 幂等：对下单、支付、合并等接口重复提交相同幂等键，预期仅生效一次、结果一致。
- 并发：同一资源并发写，预期不产生脏数据；有并发上限的接口覆盖超限请求。

## 二、节点写法

| 位置 | 内容 |
|------|------|
| L3 标题 | `正向-POST /api/customer 创建成功 [P0]`，把方法和路径写进标题 |
| `- 前置：` | 依赖的登录态、数据准备、上游状态 |
| `- 步骤：` | 请求体关键字段取值，异常用例标明「故意使用的非法/边界值」 |
| `- 预期：` | HTTP 状态码 + 业务码 + 断言字段，与接口文档逐字对齐 |

## 三、与功能用例的关系

同一功能可同时存在功能用例与接口用例，二者不合并：功能用例验界面与交互，接口用例验契约与边界。接口用例独立成 L1 `## 接口测试`，其下按接口分组。
